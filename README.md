# 🎭 舞台换景排练系统

供舞台监督排练换景使用的网页应用：管理道具与区位、按提示号录入一组组同时发生的道具转移，并在任意增删改后**按提示号全量重放**，实时展示每组提示的校验结果与最终区位分布。

技术栈：Node.js + Express + SQLite（better-sqlite3）+ 原生 JavaScript（无前端框架）。

## 业务规则

- **区位容量**：「后台」可容纳任意数量道具；其余每个区位最多容纳一件。
- **提示（Cue）**：提示号唯一，重放按提示号升序进行；每组提示包含若干条同时发生的转移。
- **同组限制**：同组内每件道具最多转移一次（数据库唯一约束 + 录入校验双重保证）。
- **整组校验、整组提交**：
  - 每条转移基于**该组变动前**的状态校验来源区位（道具必须确实在来源区位）；
  - 整组应用后，除后台外任何区位不得被多件道具占用；
  - 任一条件不满足则**整组不生效**（状态回滚到变动前），并展示全部冲突原因；
  - 因为占用校验针对的是整组完成后的状态，所以**同组互换区位是允许的**（如 A、B 两件道具互换位置）。
- **全量重放**：插入、修改或删除任意提示后，从道具初始区位出发按提示号重放全部提示，页面展示每组结果（生效 / 未生效及原因）与最终区位。
- **失败提示的冲突溯源**：重放结果为每组提示附带结构化溯源 `trace`（成功组恒为空），在失败提示旁与原有错误文案一并展示：
  - **来源区位不符**：列出道具当前区位及其**最后一次成功转移的提示号**；从未成功转移的道具标记为「初始区位」；
  - **容量冲突**：列出试算后同占该区位的全部道具，标明各道具**是否由本组转入**，及其此前最后一次成功转移的提示号；
  - 溯源随提示号顺序更新：同组转移依据组前状态，**失败组既不改变位置也不改变溯源**，只有整组生效后才把组内道具的「最后成功转移」更新为该组提示号。
- **批量平移提示号**：输入闭区间起止号与非零整数位移，先预览列出区间内每条提示的「原号 → 新号」。执行时校验：区间内至少一条提示、每个新号都是安全正整数、且不与区间外的提示号冲突；任一不满足则**整批拒绝**并标出冲突号。校验通过后在**单个数据库事务**中同时改写提示主键与转移的提示号引用（备注、转移内容与组内顺序保持不变），成功后按新号全量重放并刷新页面；提示的编辑、删除与试排预览均识别改后的号码。
- **试排预览（不写库）**：在提示录入/编辑表单可先「试排预览」。服务端沿用保存时的字段校验，把草稿按提示号插入或替换到内存中的序列，分别重放现行序列与假设序列，列出**生效状态发生变化的提示及前后冲突原因**，以及**最终区位发生变化的道具**；草稿不合法时直接返回具体错误。整个过程只在内存中重放，不写数据库；保存仍使用原有新增/替换接口。
- **现场偏差推演（不写库）**：舞台监督选择一条**已执行完的提示号作为断点**，录入**部分道具**的现场区位，未录入者沿用该断点重放后的计划区位。系统先按现有规则把提示**重放至断点**，校验现场区位（区位必须存在、普通区位不得重叠，后台不限）；校验通过后再以校正后的现场状态**接续重放断点之后的全部提示**，失败组仍按同一规则**整组不生效**。页面并列展示：断点处计划/现场区位差异、后续每条提示在原计划与现场推演中的生效状态与冲突原因（含冲突溯源）、推演结束后的最终道具区位差异。现场录入道具的溯源标记为「现场校正」。推演全程只在内存中进行，**不修改提示、道具初始区位或数据库**，复用同一套重放规则。
- **换景人员分配（逐提示岗位表）**：维护换景工作人员及其**可搬运道具名单（资格）**，页面为每条提示生成一张岗位表。岗位表**以现有重放结果为准**：
  - 仅对**整组生效**的提示分配人员；整组未生效的提示标为「**无需执行**」，不产生岗位表；
  - 生效组内**每条道具转移占一个同时执行的岗位**（岗位之间并行）；
  - **每人在同组最多承担一岗**，且必须**具备该道具的搬运资格**；
  - 服务端对整组求转移 ↔ 人员的二分图**完整匹配（Kuhn 增广路算法），不按转移录入顺序贪心分配**——存在完整匹配时贪心也可能因先到先得而失败，增广路会回溯调整先前的占用；
  - **无解时整组标为「人手不足」**，列出**未覆盖道具**，**不输出部分岗位表**；
  - 人员资格、人员、道具或提示发生任意变化后，岗位表都按最新数据**整表重新计算**。

## 快速开始（Docker，一条命令）

```bash
docker compose up --build
```

该命令会自动完成：构建镜像 → 安装依赖 → 首次启动时初始化 SQLite 数据库（建表 + 写入示例数据）→ 启动服务。

启动后访问：**http://localhost:3000**

> 示例数据包含 5 个区位、5 件道具和 3 条提示（10 / 20 / 30 号）。其中 30 号提示故意与 20 号冲突，用于演示「整组不生效 + 冲突原因」；10 号提示演示「同组互换区位」。另含 3 名换景人员（张三 / 李四 / 王五）及搬运资格：10 号提示演示「整组完整匹配」（按转移顺序贪心会失败，张三、李四需互相调剂）；20 号提示的宝剑无人有资格，演示「人手不足 + 标出未覆盖道具」；30 号提示整组未生效，岗位表标为「无需执行」。

停止并删除容器（数据保留在命名卷 `stage-data` 中）：

```bash
docker compose down          # 如需同时清空数据：docker compose down -v
```

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 网页地址 / 端口 | `http://localhost:3000` | 修改 `docker-compose.yml` 中 `ports` 左侧端口即可换宿主机端口，如 `"8080:3000"` |
| `PORT` | `3000` | 容器内服务监听端口（环境变量） |
| `DATA_DIR` | 容器内 `/app/data`，本地 `./data` | SQLite 数据文件目录，不存在时自动创建并初始化 |

## 本地开发（不用 Docker）

要求 Node.js ≥ 18：

```bash
npm ci        # 安装依赖
npm start     # 初始化数据并启动，访问 http://localhost:3000
```

删除 `./data` 目录后重启即可重置为示例数据。

## 页面使用

1. **① 区位**：增删区位（「后台」为固有区位不可删；被道具或提示引用的区位不可删）。
2. **② 道具与初始区位**：新增道具并指定初始区位（非后台区位初始只能放一件）；可改初始区位、删除道具。
3. **③ 录入提示**：填提示号与备注，添加若干条「道具 / 来源 / 目标」转移后保存；点击列表中的「编辑」可修改整组。
   - **🧪 试排预览（入口：③ 录入提示表单内的「试排预览（不保存）」按钮）**：保存前先按提示号把草稿插入或替换到内存中的序列，不写库。面板会展示哪些提示的生效状态发生了变化（现行 → 假设，含冲突原因），以及最终区位发生变化的道具；草稿不合法时显示具体错误。表单内容一旦改动，旧预览自动清除，需要重新预览。
4. **④ 提示序列**：按提示号排列，每条提示标注 ✓ 已生效 / ✗ 整组未生效及冲突原因，失败提示下方附结构化「冲突溯源」（来源不符的道具当前区位与最后成功转移提示号；容量冲突的同占道具、是否本组转入及各自最后成功转移提示号），可编辑、删除。
   - **批量平移提示号（入口：④ 卡片顶部）**：填起始号、结束号（闭区间）与非零整数位移 → 点「预览平移」列出区间内每条提示的原号 → 新号；若新号与区间外提示冲突会逐条标红并禁用执行。确认无误后点「执行平移」，服务端在单个事务中完成整批改写并全量重放，页面随即刷新为新号。输入一旦改动需重新预览。
5. **⑤ 重放结果与最终区位**：逐组展示重放结论（失败提示同样附冲突溯源），看板展示全部提示重放后的最终道具分布。
6. **⑥ 现场偏差推演（入口：页面底部同名卡片，整页宽）**：选择已执行完的提示号作为断点 → 在每件道具的「现场区位」下拉中选择实际位置（留空＝沿用断点处计划区位）→ 点「🎯 开始现场推演」。面板并列展示：①断点处计划/现场区位差异；②断点之后每条提示在原计划与现场推演中的生效状态、冲突原因与结构化溯源（翻转的提示会高亮，失败组仍整组不生效）；③推演结束后的最终道具区位差异。现场区位重叠或不存在时整次推演被拒绝并标出冲突区位；推演仅在内存中进行，不写库。
7. **⑦ 换景人员与搬运资格**：新增/删除工作人员；在每行勾选该人员**可搬运的道具**（勾选即保存，整份名单替换）。删除道具会同步移除相关资格。
8. **⑧ 逐提示岗位表**：按提示号展示排岗结果——✓ 已排 N 岗（逐条列出「道具 / 路线 / 上岗人员」，每人同组仅一岗）、✗ 人手不足（列出未覆盖道具，不输出部分岗位表）、— 无需执行（该提示整组未生效）。人员资格或提示一有变化，岗位表立即按最新数据重算。

> 访问入口与地址：`docker compose up --build` 后用浏览器打开 **http://localhost:3000**；试排预览按钮位于页面「③ 录入提示」表单中，现场偏差推演位于页面底部「⑥ 现场偏差推演」卡片，「⑦ 换景人员与搬运资格 / ⑧ 逐提示岗位表」紧随其后（默认宿主机端口 **3000**；改为 `"8080:3000"` 后即访问 http://localhost:8080）。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态：区位、道具、提示（含转移）、重放结果、最终区位、人员（含资格）与岗位表；重放结果每组含 `trace` 结构化冲突溯源（`sourceMismatches`：道具当前区位与最后成功转移提示号，`lastMovedCue` 为 `null` 表示初始区位；`capacityConflicts`：试算后同占道具、`movedIn` 是否本组转入及各自最后成功转移提示号） |
| GET | `/api/crew` | 人员名单及各自可搬运道具（资格） |
| POST / PUT / DELETE | `/api/crew` `/api/crew/:name` | 新增人员（可带初始 `props` 资格名单）/ 整份替换某人的可搬运道具名单（`{props: [...]}`，道具须存在）/ 删除人员（资格级联删除）；成功后岗位表重算 |
| GET | `/api/staffing` | 逐提示岗位表（按最新数据即时重算）：每组 `{number, status, posts, uncoveredProps}`；`status` 为 `staffed`（已排岗，`posts` 每条 `{prop, from, to, person}`，每人同组一岗且须有资格）、`understaffed`（无完整匹配，`posts` 为空，`uncoveredProps` 标出未覆盖道具）、`skipped`（整组未生效，无需执行） |
| POST / DELETE | `/api/locations` `/api/locations/:name` | 新增 / 删除区位 |
| POST / PUT / DELETE | `/api/props` `/api/props/:name` | 新增 / 改初始区位 / 删除道具 |
| POST / PUT / DELETE | `/api/cues` `/api/cues/:number` | 新增 / 整组替换 / 删除提示 |
| POST | `/api/cues/shift/preview` | 批量平移预览：校验并列出闭区间内每条提示的原号→新号及冲突号，**不写库** |
| POST | `/api/cues/shift` | 批量平移执行：校验（区间非空、新号均为安全正整数、不与区间外冲突）通过后单事务改写主键与转移引用并全量重放；冲突时返回 409 与冲突号列表，整批拒绝 |
| POST | `/api/cues/preview` | 试排预览：沿用字段校验，在内存中按提示号插入/替换草稿后分别重放现行与假设序列，**不写库**，返回生效状态变化的提示（含前后冲突原因）与最终区位变化的道具；草稿不合法时返回 400 与具体错误 |
| POST | `/api/onsite/simulate` | 现场偏差推演：入参 `{breakpoint, overrides}`（`overrides` 为 `[{prop, location}]` 或 `{prop: location}`，空 location＝沿用计划）。先按现有规则重放至断点，校验现场区位存在且普通区位不重叠，再以校正后现场状态接续重放后续提示，**不写库**；返回断点处计划/现场差异（`breakpointDiff`）、后续各提示原计划与现场推演的生效状态/冲突原因/溯源（`followCues`）、双方完整重放（`plan` / `onsite`）与最终区位差异（`finalDiff`）；现场状态不合法时返回 400 及 `validation.conflicts` 冲突区位 |

所有写操作成功后会重新执行全量重放与岗位表计算，并返回最新状态。

## 项目结构

```
├── server.js            # Express 服务与 API
├── db.js                # SQLite 连接、建表、首次启动写入示例数据
├── replay.js            # 核心：按提示号全量重放、整组校验与断点接续重放（纯函数，试排预览与现场偏差推演共用）
├── staffing.js          # 核心：以重放结果为准的逐提示岗位表（整组二分图完整匹配，非贪心；人手不足不输出部分岗位表）
├── public/              # 原生 JS 前端（index.html / app.js / style.css）
├── Dockerfile           # 多阶段构建（构建阶段含编译工具，运行阶段精简）
├── docker-compose.yml   # 一条命令启动
└── data/                # SQLite 数据目录（运行时生成，勿提交）
```
